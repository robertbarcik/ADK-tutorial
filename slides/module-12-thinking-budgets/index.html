Thinking budgets

Trade latency for reasoning quality

One knob, big effect.

What thinking is

Gemini 2.5+ models do an internal reasoning pass before producing the final answer. The reasoning tokens don't appear in the output; they're counted separately as thoughts_token_count.

You set a budget — a ceiling on internal reasoning — and Gemini spends up to that much thinking.

user prompt ──▶ [internal thinking: up to N tokens] ──▶ final answer
                      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                      invisible in output; billed separately

The knob

ThinkingConfig(
    thinking_budget=N,       # 0 = off; 2048+ = serious reasoning
    include_thoughts=False,  # set True to see the reasoning in output
)

Or, on Gemini 3+, the coarser preset:

ThinkingConfig(thinking_level=MINIMAL | LOW | MEDIUM | HIGH)

We use thinking_budget (int) — works on 2.5 and later.

Direct comparison

Problem: multi-step profit-margin calculation, 3 breads.

── thinking_budget=0 ──
latency: <1s
tokens — input: 158, thoughts: 0, output: 702

── thinking_budget=4096 ──
latency: 11.06s
tokens — input: 158, thoughts: 1109, output: 702

Same input. Same output length. Big latency + token gap. The 1109 thoughts are reasoning the model did internally.

The even-better demo

USER: What is the sum of all prime numbers between 20 and 50?

── fast_agent (thinking=0)    0.76s
   Answer: 255  ← wrong

── thinking_agent (thinking=2048)    9.98s
   Answer: enumerated primes (23, 29, 31, 37, 41, 43, 47),
           sum = 251  ← correct

The fast agent got a different — and wrong — answer. That's the quality difference, visible.

Inside an ADK agent — BuiltInPlanner

from google.adk.planners import BuiltInPlanner
from google.genai import types

thinking_agent = LlmAgent(
    name="thinking_agent",
    model="gemini-2.5-flash",
    instruction="Reason carefully for multi-step problems.",
    planner=BuiltInPlanner(
        thinking_config=types.ThinkingConfig(thinking_budget=2048),
    ),
)

BuiltInPlanner wraps ThinkingConfig so ADK plumbs it through to Gemini. Everything else about the agent is unchanged.

When thinking earns its keep

Crank the budget for
  • Multi-step reasoning (the profit-margin problem)
  • Code debugging (trace through logic)
  • Hard math, proofs, arithmetic
  • Multi-constraint planning / scheduling
Skip thinking for
  • Factual lookups ("capital of France")
  • Text transformations (summarize, translate, rewrite)
  • Simple classification (spam? yes/no)

Production pattern

Route on query type.

Cheap, fast router with thinking=0.
Delegates to a thinking-heavy specialist or a fast one per query.

Gemini 3+ — thinking_level

SettingMaps to roughly
thinking_level=MINIMALOff / very low budget
thinking_level=LOW~1K thought tokens
thinking_level=MEDIUM~4K thought tokens
thinking_level=HIGHUnlimited; model decides

Use thinking_level on 3+ when you don't want to pick a number. Use thinking_budget on 2.5 (and 3+) when you want precise control.

Gemini-only property

Thought signatures persist across multi-turn tool calls.

No reasoning reload. Thinking carries through the conversation.
No other frontier model ships this as of April 2026.

What to carry forward

Thinking is a knob, not a default.

Crank it for hard problems. Leave it at 0 for easy ones. Route per query.
