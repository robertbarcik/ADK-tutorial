Live API voice agent

The biggest Gemini unlock

Bidirectional audio · VAD · interruption

As of April 2026

The single most differentiated capability
Gemini ships that no competitor replicates cleanly.

What Live does

  • Bidirectional audio. Voice in, voice out, over a single WebSocket.
  • Voice Activity Detection (VAD). Gemini decides when you've stopped talking and starts responding.
  • Interruption. Talk over Gemini mid-response and it stops immediately, listens to the new input.
  • Sub-second latency on happy-path sessions.

Competitors: OpenAI's Realtime API is the closest; different semantics, different pricing. Anthropic has no direct equivalent.

Live vs run_async

run_async (M01-M12)

Request/response cycle. Hand in a message, events stream back, turn ends.

Text in, text out. No notion of a continuous session beyond event history.

vs

run_live (this module)

Open bidirectional WebSocket. Stream chunks of audio into a queue; chunks of response audio stream back, in parallel.

For as long as the session is open. Built for voice, not turn-based chat.

Three primitives you need

PrimitiveRole
LiveRequestQueuePush user input into (text chunks or audio blobs)
Runner.run_live(...)Async generator yielding server events; runs until queue closes
RunConfig(response_modalities=[...])Output shape: "TEXT", "AUDIO", or both

Voice Activity Detection + Interruption

Both server-side, both on by default. Tune via RealtimeInputConfig in RunConfig:

RealtimeInputConfig(
    automatic_activity_detection=AutomaticActivityDetection(
        silence_duration_ms=1000,     # respond after 1s silence
        prefix_padding_ms=200,        # 200ms context before detected speech
    )
)

Lower silence_duration_ms = snappier but false triggers. Higher = natural but noticeable delay. 1000ms is a sensible conversational default.

Fair warning

Live is preview-tier and brittle

Transient server errors (code 1011 "Internal error encountered", connection drops) show up on free-tier keys. The code is correct; the endpoint is unreliable. Logged in DEMOS_BROKEN.md.

What to do

Learn the API shape today. Run the audio demo in a few weeks, or on a paid tier, or against Vertex AI. The concepts are durable; this month's version-string is not.

Pricing

Audio is billed by minute, not by token.

When Live is the right tool

Use Live for
  • Real-time conversational voice
  • Interruption handling — users will talk over you
  • Sub-second latency requirements
  • Open-session continuous dialog
Don't use Live for
  • Transcription (use a dedicated STT service)
  • TTS playback of pre-computed answers (use TTS)
  • Non-interactive voice (narration of a script)

What to carry forward

Live is for real-time conversational voice.
The API is run_live + LiveRequestQueue.
The model names rotate.

Preview-tier fragility is real; the teaching of the shape is durable.
