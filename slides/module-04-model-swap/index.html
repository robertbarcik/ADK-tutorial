What LiteLlm actually is

ADK was written by Google; it speaks Gemini natively. Every other model needs a translation layer. That layer is LiteLLM — an independent open-source library that sits between your code and ~100 LLM providers.

Requests are OpenAI-shaped on the way in. LiteLLM translates them to whatever the target provider expects, sends, translates the response back.

ADK's LiteLlm wrapper is a thin adapter exposing this library as an ADK model. Google wrote it so they didn't have to write a custom shim per vendor.

Request flow

   ADK Agent
      │ OpenAI-shaped request
      ▼
   LiteLlm wrapper
      │
      ▼
   LiteLLM ─── Anthropic format ──▶ OpenRouter ──▶ Anthropic API
      ▲                                               │
      └───── Anthropic response ◀── OpenRouter ◀──────┘
      │ OpenAI-shaped response
      ▼
   ADK Agent (sees the shape it expected)

Two translations per call. Both handled by LiteLLM. The catch: bumping google-adk and litellm independently can break tool-call shapes — that's why requirements.txt pins them together.

One OpenRouter key replaces five provider keys. Skip :free tiers for real work — rate-limited, unreliable.

What to notice in the output

  • Answers vary in style, converge on content. Every model explains tool-calling; none hallucinate badly on a vanilla concept. Quality differences only show on hard prompts.
  • Latency varies ~3x. Open-weight models through their current providers are slower than the hosted frontier ones. For tool-heavy agents this matters; for Q&A usually not.
  • Reasoning traces leak sometimes. Some models (Qwen, DeepSeek) emit a thought process even when not asked. Pick a non-reasoning variant or pass extra_body={"reasoning": {"effort": "low"}}.
Bonus

Local models via Ollama

Zero cost per call. No network. One prefix to get right.

Setup

# One-time, on your machine
brew install ollama         # or ollama.com download
ollama serve                # starts http://localhost:11434
ollama pull qwen3:8b        # downloads the model

# Then in your ADK code
agent = LlmAgent(
    model=LiteLlm(model="ollama_chat/qwen3:8b"),  # ← this exact prefix
    ...
)

The gotcha

ollama_chat/ ← use this.

ollama/ ← not this.

The plain ollama/ prefix hits the completions API. Tool calls become text the model has to produce exactly; it fails; infinite loop. Use ollama_chat/ for the chat-completions API with real function-calling.

Interlude · Agentic Design Patterns

Prompt priority tiers

Instructions that survive pressure.

The problem

When you swap models, instructions that worked on Claude sometimes partially fail on GPT. One model reads your instruction all the way through; another prioritizes the earliest tokens.

Long instructions also get truncated under context pressure — long system prompts plus long tool descriptions plus long chat history can force ADK to drop parts of what you wrote.

Structure your instruction so the most important bits survive.

Three tiers

Tier 1 — Invariants (top of prompt)

Rules the agent must obey always. Safety gates, hard refusals, format constraints. Short, declarative. "Never include credit card numbers."

Tier 2 — Core behavior

The job description. What the agent is for. "You help engineers debug build failures by reading logs and suggesting fixes."

Tier 3 — Preferences (bottom, OK to lose)

Communication style — length, tone, markdown. "Prefer bullet points over paragraphs."

A priority-tiered instruction

# INVARIANTS (highest priority; never violate)
- Do not execute code; only suggest code to run.
- Refuse to generate credentials, API keys, or secrets.
- If asked about a language you don't know, say so; do not guess.

# CORE BEHAVIOR
You are a coding-help assistant for a small engineering team.
For any code question: identify language, give a minimal example,
explain in 2-3 sentences.

# PREFERENCES
- Use fenced code blocks for code.
- Keep prose short; engineers prefer code they can read.

Top survives pressure. Bottom does not. Rank accordingly.

When to swap models in production

Failover

A provider has an outage. One-line config change sends traffic to GPT or Gemini. This is the main reason to bother with LiteLLM at all.

Per-task capability

GPT reasons better on obscure math; Claude writes cleaner code; Gemini grounds in live web results. Pick the right tool per sub-agent.

Cost optimization

Cheap queries to Haiku / 4o-mini / Flash-lite; hard queries to Opus / GPT-5 / Pro. Callbacks (M07) and eval (M09) give you the hooks.

The rule

Vendor-neutrality is a capability, not a habit.

Swap models with evaluation, not on hunches.
